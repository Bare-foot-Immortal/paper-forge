## 3. 关键需求验证

### 3.1 需求 2：题量与占比自定义

蓝图 20/10/10 下 6 张卷子的实测题量：

| 卷 | 单选 | 多选 | 判断 | 合计 |
|---|---|---|---|---|
| A～F（6 张，全部一致） | 20 | 10 | 10 | **40** |

结论：**符合**。（`verify_release.py` 逐卷断言）

### 3.2 需求 3：一轮覆盖题库全部题目 + 末尾补题

- 轮长自动计算：`覆盖题库全部题目需 2 张/轮（单选 101÷20=6张，多选 32÷10=4张，判断 30÷10=3张）`
- 6 张卷子共 240 题，去重后命中题库 **163 / 52 题** → 覆盖完整
- 补题实测（多选 32 题 / 每卷 10 题）：第 4 张 = **2 道新题 + 8 道本轮已出现的题目**，总题量仍为 10
- 轮长手动设为 3 时：仍生成 6 张 × 40 题，但 `coverage_ok = False` 且给出未覆盖题目清单与明确告警

结论：**符合**。

### 3.3 需求 4：多选题「（定）」固定顺序

以需求原文题目构造用例（`BC（定）`：`A.3～4 B.4～5 C.垂直 D.平行`）：

| 校验点 | 结果 |
|---|---|
| 开启打乱时该题 `shuffled` | False（未打乱） |
| 导出选项顺序 | `3～4 / 4～5 / 垂直 / 平行`（与题库一致） |
| 导出答案 | `BC`（与题库一致） |
| 50 次随机重复 | 全部保持 |

对照：同一卷中非定多选 `ABCD` 被打乱为 `转包…/无资质…/未经论证…/发包给…`，答案仍为 `ABCD` 且按新字母取到的文本集合与原答案完全一致。

结论：**符合**，且与"非定题正常打乱"形成有效对照。

### 3.4 需求 5：单选与多选选项可分别打乱

| 场景 | 结果 |
|---|---|
| 单选/多选均开打乱 | 6 张卷子全部题目按新字母作答，命中文本与原答案一致（0 项不符） |
| 关闭打乱 | 选项与答案保持题库原样 |
| 判断题 | 始终不打乱，答案输出「正确/错误」 |

结论：**符合**。

## 4. 缺陷与修复记录

| 编号 | 现象 | 根因 | 修复 |
|---|---|---|---|
| D-01 | 打乱后答案等价性用例失败 | 用例断言了答案元素**顺序**；非定多选题答案本质是无序集合 | 用例改为集合比对；同时新增"定题答案顺序严格保持"用例 |
| D-02 | JSON 题库中判断题导入失败 | JSON 各行宽度不齐，位置回退映射把答案列错位 | JSON 读取统一补齐为 12 列标准布局 |
| D-03 | 构建脚本无法执行（中文乱码报错） | `.ps1` 为 UTF-8 无 BOM，Windows PowerShell 5.1 按 GBK 解析 | 为脚本写入 UTF-8 BOM |
| D-04 | 打包报 `WinError 5 拒绝访问` | 上一轮 GUI 测试残留的进程占用 `dist\PaperForge.exe` | 清理进程；构建脚本新增占用检测与旧产物清理 |
| D-05 | 合并导出时"答案不分离"丢答案 | 合并分支未处理 `answers_separate=False` | 合并分支补上答案区渲染（docx/html/txt 三处） |
| **D-06** | Word 样例的多选题全部报「缺少答案」 | 答案 token 正则只接受 `B、D` 这种带分隔符写法，不接受 `ABCD` 连写 | 正则改为 `[A-H]{1,8}(?:[、,，/][A-H]{1,8})*` |
| **D-07** | Word 样例出现「选项少于 2 个 / 答案字母超出选项范围」 | 选项识别要求字母后必须有分隔符，而源文件写作 `A明确内容`、`C  2.5m`，且选项标记会紧贴中文出现（`…人员B.项目负责人…`） | 重写选项扫描器 `_iter_option_marks`：接受上述无分隔符写法，同时排除 `BIM`、`ABC` 等拉丁串 |
| **D-08** | Word 题干被截断并产生伪造题目 | 粘连切分正则把选项正文里的 `2.9米` 当成新题号（`2.` + `9米`） | 题号/粘连正则改为「小数点后不得紧跟数字」 |
| **D-10** | Excel 把全部选项写在一列（`A.甲 B.乙`）时完全不识别 | `_detect_header` 要求 ≥2 个选项字母列，单列「选项」不满足 → 退化为按位置猜；单列展开逻辑只接在 Word 表格上 | 列头识别接受「选项」合并列，命中后先展开成 选项A…选项H 再解析（Excel/CSV/JSON 与 Word 共用） |
| **D-11** | 没有「题型」列的 Excel 每行都报「题型无法识别」 | 表格通道要求题型必须显式给出；段落解析器早支持由答案形态推断，表格通道未接上 | 题型列为空时由答案推断（多字母→多选、`√×对错`→判断、单字母→单选）；题型列写了无法识别的值仍报错 |
| **D-12** | 列头写在第 6 行以后时退化为按位置猜，猜中也伴随大量坏行 | 列头只在**前 5 行**内查找 | 扫描范围放宽到 20 行 |
| **D-13** | 英文列头、`选项1`、`A选项`、全角/换行列头只能靠位置回退碰巧成功 | 选项列正则只认「裸字母 / 选项+字母」 | 新增 `_option_letter_of_header()`，兼容 `选项A`/`A选项`/`选项1`/`optionA`/`选项（A）` 等；列头比对时去空白与换行 |
| **D-14** | 无选项列的选择题报错为「答案字母 B 超出选项范围」，不易理解 | 校验在答案解析阶段暴露 | 提前给出「单选题缺少选项（只识别到 N 个选项列），请检查列头」 |
| **D-09** | exe 的 CLI 输出经管道捕获为乱码/丢失，自动化无法取结果 | GUI 版 exe 写 `CONOUT$`，管道捕获不可靠 | 新增 `--log FILE`（与刷题匠一致），输出同时落盘 UTF-8 |

## 5. 已知限制

1. 题目为纯文本，不支持图片题与公式图片；
2. 判断题答案按「正确 / 错误」输出；
3. 某题型题库量小于每卷配额时，同一张卷子内会出现重复题目（已告警，属需求允许的补题行为）；
4. 部分杀毒软件对 PyInstaller 单文件 exe 敏感，可加入白名单或用源码自行打包（已提供 `build_exe.ps1`）；
5. 界面自动化采用"无头自检"（真实 Tk 对象 + 全流程调用），未做像素级 UI 自动化。

## 6. Excel / CSV 排布兼容性（v1.2.1 / v1.1.1 起放宽）

**不必照着示例逐列对齐。** 软件按「列名」理解表格，识别不到列名时才按列位置兜底。

### 6.1 这些都支持

| 情况 | 说明 |
|---|---|
| 首行是题库标题 | 列头从第 2 行开始也能找到（**前 20 行**内均可） |
| 标题与列头之间有空行 | 支持 |
| 列头写在第 15 行 | 支持（旧版只扫前 5 行） |
| 列的顺序与示例不同 | 答案/解析放最前、题干放最后都可以 |
| 选项列乱的 | `选项C` 排在 `选项A` 前面也能正确归位 |
| 「题型」列放在最后一列 | 支持 |
| 多个工作表 | 自动挑「能识别列头 / 行数最多」的那张表（说明页会被跳过） |
| 完全没有列头 | 按标准列位置解析（题型/题干/选项A–H/解析/答案） |
| 列头写法不同 | `题目类型`/`题干`/`题干内容`/`A选项`/`选项 B`/`选项1`/`optionA`/`正确答案`/`答案解析` 等均识别 |
| 列头带空格/换行/全角 | 支持（自动归一化） |
| 题型写成 `单选题（每题1分）` | 支持（含关键字即可） |
| 选项全部挤在一列 | `选项` 列内容写 `A.甲 B.乙 C.丙 D.丁` → 自动拆开 |
| 没有「题型」列 | 由答案推断：多字母→多选、`√×对错`→判断、单字母→单选 |

### 6.2 仍需人工整理的情况

| 情况 | 建议 |
|---|---|
| 无列头且列顺序不符合标准布局 | 加一行列头最稳妥 |
| 选择题没有选项列 | 无法作答，软件会报「单选题缺少选项（只识别到 0 个选项列）」 |
| 「题型」列写了无法识别的值（如 `选择题`） | 软件会明确报「题型无法识别：'选择题'」，不会猜测 |
| 选项中间有空列 | 报「选项不连续（中间存在空列）」 |
| 题干合并了多行/单元格 | 建议每行一题、题干在一个单元格内 |

所有无法导入的行都会以「行号 + 原因 + 题干片段」列出，按提示修补即可。
